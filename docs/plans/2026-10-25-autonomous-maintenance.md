## Evidence and implementation

Bing's authenticated Live URL test fetched the exact homepage with HTTP 200, reports "URL can be indexed by Bing" and "No SEO/GEO issues found". Its actual Bing Index remains discovered/not crawled. This excludes a current homepage fetch/robots failure in that test; Bing's scheduling/quality decision remains unspecified. No indexing request was made. Do not claim a repair caused actual indexation.

The selected repair is small and reversible: permit the already-injected Cloudflare Web Analytics beacon in CSP using only its documented HTTPS origins; cache public, query-free catalog directory HTML for five minutes using Cloudflare's Cache API. Cache keys include Worker version, content release and original locale path. Never cache errors, authenticated requests, HEAD fills, filtered URLs, or HTML/Markdown under the same key. A deployment automatically changes the cache namespace.

Add a read-only crawler health command that records HTTP status, robots, canonical, HTML language, sitemap allowlist and timing, with explicit synthetic-crawler limitations. Fix source detail caching so a changed review/update marker or expired local detail cache refreshes the original public record rather than preserving it indefinitely.

An alternative is to change zone-wide bot or firewall settings, but Bing's successful native test provides no reason for that intervention. A broad page/content expansion would also conflict with the established search scope. The implementation retains existing content and concentrates on serving speed, measurement and reliable maintenance.
